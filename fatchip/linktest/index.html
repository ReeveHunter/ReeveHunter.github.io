Link Test

What does your MIDI adapter actually pass to the Game Boy?

This browser has no Web MIDI. Open this page in Chrome, Edge or Opera on a computer (Safari and Firefox don't support Web MIDI).
SysEx permission was refused, so the SysEx tests are switched off. To allow it, click the MIDI icon in the address bar (or the site settings), allow MIDI device control, and reload.

How it works

  1. Flash Fat Chip GB v0.3 or newer and connect the Game Boy to your MIDI adapter as usual.
  2. On the Game Boy: B for Setup, go down to LINK TEST, press A. Press A again to zero the counters.
  3. Here: connect, pick the output that feeds the Game Boy, and press Zero so both sides start from nothing.
  4. Run the tests one at a time (or all of them) and compare the Game Boy's screen with the expected screen on this page.

The tests play on a channel no Game Boy voice listens to (16 by default), so they're silent. Nothing is saved on the Game Boy.

Tests

Game Boy should read

If your interface uses running status, BYTES can be a bit lower; if it sends active sensing, BYTES is higher by the SENSE count. Neither is a problem. The other numbers should match exactly.

Reading the results

Everything matchesThe adapter passes notes, clock and SysEx cleanly. Fat Chip can use MIDI clock and SysEx with the Game Boy.
SYSEX F0 / F7 stay at 0The adapter doesn't forward SysEx. Fat Chip will talk to the Game Boy with notes, CCs, bends and program changes only (that's the current plan anyway).
SysEx counts rise but LEN or SUM are wrongSysEx gets through but bytes are lost or changed. Try the short one: if it's right and the long ones aren't, the adapter's buffer is too small for long messages.
CLOCK stays at 0The adapter filters MIDI clock. Fat Chip GB will keep its own tempo and follow the C64's downbeat CC instead.
"Clock between / inside" loses NOTE ONS, or NO STATUS goes above 0The adapter drops a byte after each clock (a known stock-Arduinoboy problem). Don't send clock to the Game Boy port.
NOTE ONS short on the plain notes testBytes are being lost even without clock or SysEx: check cables, and that nothing else is sending to the same port.
