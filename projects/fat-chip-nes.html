Where it fits in Fat Chip

Fat Chip pools every oscillator in the room into one fat chiptune instrument for live playing: ambient pads, fat leads, drones, glitch and warble.

PartHardwareJob
Fat Chip 64Commodore 64 + Kerberos MIDI cartridgeThe controller. Plays the SID and sends MIDI to everything else.
Fat Chip GBGame Boy + TeensyboySound module for the Game Boy's four channels.
Fat Chip NESNES + Everdrive N8 Pro + a MIDI bridgeSound module for the NES's five channels. Takes the slot the MidiNES fills today.
  • In tandem: Fat Chip 64's setup screen lists Fat Chip NES next to MidiNES. Fat Chip 64 already knows the MidiNES's channel layout, so Fat Chip NES keeps the same one-voice-per-channel layout by default and adds what the MidiNES can't do: even pitch bends, built-in vibrato, envelopes, DMC chord loops. Paddle and keyboard CCs from Fat Chip 64 map to Fat Chip NES parameters, the same way they do for Fat Chip GB.
  • Standalone: like Fat Chip GB, it also works on its own from Logic, a keyboard, or a Raspberry Pi playing MIDI files at a show. Plain MIDI from any source should sound right.
  • All three together: SID, Game Boy and NES voices stack into one instrument, with Fat Chip 64 deciding which device plays what.

Getting MIDI to the cart

The Everdrive N8 Pro has a USB port that a running program can read, and SynthNes already proves the link works for live MIDI control. MIDI doesn't arrive in a form the cart understands, though, so something has to sit in between and translate.

Main plan: a small bridge box

  • In: a MIDI DIN input, so it sits in the same chain as the MidiNES today (Kerberos MIDI out → thru/splitter → bridge). Optionally also a USB MIDI port for a computer.
  • Out: a USB host port that talks to the N8 Pro as a serial device and writes bytes to it.
  • Jobs: pass on only the NES's MIDI channels, buffer bursts so nothing is dropped, and optionally pre-digest messages into a compact form for the ROM. The long-term goal is for the ROM to handle raw MIDI itself, so the bridge can stay simple.
  • Candidates: a Raspberry Pi Pico (USB host through PIO-USB), a Teensy 4.1 (has a USB host port), or a Raspberry Pi Zero 2 (Linux, easiest to program, slower to boot). Plus a standard opto-isolated MIDI input circuit.

For development and DAW use: a browser bridge

A page on this site can do the same job with no hardware, which is the fastest way to get the first link test running:

  1. Logic → IAC Driver. Enable the IAC bus in Audio MIDI Setup and route tracks to it.
  2. IAC → web page. A page on this site uses Web MIDI (navigator.requestMIDIAccess()) to listen. Chrome or Edge only.
  3. Web page → cart. Web Serial (navigator.serial) writes bytes to the N8 Pro's USB serial port. Selecting the port requires one click; after that the page can reconnect automatically.
  4. NES. The ROM polls the cart for incoming bytes and writes to the APU.

The page can send compact pre-digested messages instead of raw MIDI where that helps, but the long-term goal is for the ROM to handle raw MIDI itself so a Pi can drive it with no special software. The same page also runs in Chromium on a Pi.

Tempo-synced features (echo, arpeggiator) need tempo. The page forwards MIDI clock (24 pulses per quarter note) from Logic, or the ROM falls back to an internal tempo set by CC.

Two ways to play it

  • Channel mode (default, what Fat Chip 64 expects): one MIDI channel per NES voice, like the MidiNES, with configurable channel numbers so it coexists with other gear.
  • Fat mode: play one part on one MIDI channel and the ROM spreads it across all five channels itself. Useful standalone from a keyboard or DAW, or when Fat Chip 64 hands the NES a whole chord.

Both modes share one engine: input, cents-based pitch, period tables, envelopes, LFOs and DMC playback. Fat mode adds the voice allocator and layering on top. Open: one ROM with a switch (program change or setup screen), or two ROM targets from the same engine if ROM space runs short, since fat mode spends its sample space on chord and interval loops rather than drum kits.

Keep from MidiNES

  • Full access to every channel: two pulses, triangle, noise, DMC, including sweep, duty, volume and length registers. One MIDI channel per NES voice, with channel numbers configurable so it coexists with other gear.
  • Fast CC response, not tied to vblank. Modulation (vibrato, envelopes) runs on its own fixed internal tick so it sounds the same regardless of how much data is arriving.
  • Decay on CC11, expanded into a full ADSR.
  • The pulse modulation hack (CC12/CC06 in MidiNES).
  • Keyboard-mapped sample banks, DMC pitch, and the "wave traveller," with better-curated kits.
  • A visualizer showing notes, CCs and active voices. Also useful for debugging.

Fix #1: pitch bend

  • Work in cents, not register units. The NES sets pitch with a period register, so equal register steps are tiny bends at low notes and huge ones at high notes. The ROM converts every pitch offset (bend, vibrato, glide, detune) to cents, sums them, then converts once to a period by interpolating between semitones in a period table. A bend sounds the same size in every octave. This is the same "sum in semitone space, convert once" approach as the Scripter plugin.
  • Use all 14 bits of the pitch bend message.
  • Bend range via RPN 0, default ±2 semitones, adjustable to ±12 or ±24.
  • Bend is channel state: a held bend applies to new notes, like a normal synth.
  • Clean/clicky switch per channel. Writing a pulse channel's high period byte restarts the waveform and clicks. Clean mode only writes the high byte when it changes (with the standard workaround to avoid even that); clicky mode just writes it.
  • Known limit: at the top of the range the period register is coarse, so very high bends step audibly. That is the hardware.

Fix #2: built-in vibrato

  • Standard controls: CC1 (mod wheel) for depth, plus CC76 rate, CC77 depth, CC78 delay.
  • Depth in cents, so vibrato is even across octaves.
  • Shapes: sine, triangle, square, saw, random (sample and hold).
  • Delay and fade-in per note, so vibrato blooms after the attack.
  • Tremolo and duty modulation from the same LFO engine. Tremolo is steppy with only 16 volume levels, which suits the sound.
  • Optional tempo sync for LFO rate.

Expression features

Carried over from the Logic Scripter work so they no longer need Logic:

  • Portamento/glide: CC5 time, CC65 on/off, legato mode, multiple curve shapes including S-curve.
  • ADSR volume envelopes for pulse and noise. Triangle has no volume control, so it gets gate only (see the $4011 trick).
  • Pitch envelopes for attack and release bends, and for synthesized drums (triangle kick, noise snare).
  • Hold/latch for detune and the mod hack, so new notes inherit them.
  • Program changes recall presets baked into the ROM by the builder.
  • Panic on CC120/CC123.

Arpeggiator

The defining chiptune trick: hold a chord, and one channel cycles through its notes fast enough to imply the chord.

  • Modes: up, down, up-down, as-played, random, and "tracker" mode (fixed semitone offsets like 0 4 7 from the played note, the classic 0xy effect).
  • Rate: free (in NES frames, where 1 frame is the classic buzzy chord) or tempo-synced divisions.
  • Octave range 1 to 4, and an optional gate length per step.
  • Latch so the arp keeps running after keys are released.
  • Works with pitch bend and vibrato, since everything sums in cents before conversion.

Echo

Built into the ROM so it replaces Logic's MIDI FX echo, and something most trackers only fake by hand.

ParameterOptions
Repeats1 to 8 (or more if RAM allows)
Velocity curveLinear, exponential (feedback %), or a custom curve drawn in the builder. Mapped to NES volume steps, so quiet tails get grainy, which is fine.
TimingTempo-synced divisions (1/4, 1/8, dotted, triplet) from MIDI clock, or free time in milliseconds
RoutingSame channel, or to another channel (e.g. pulse 1 echoes onto pulse 2), or ping-pong between the two pulses
Per-repeat changesOptional: duty cycle steps, pitch offset per repeat (rising/falling echoes), shortened gate

Priority: newest note wins

Each NES channel plays one note at a time, so echoes and new notes compete for the same channel. The default rule is that new note presses, and their own echoes, always take priority over echoes of older notes.

  • Cancel or duck (per patch). Cancel: a new note-on drops every pending echo of older notes. Duck: older echoes are only skipped while a newer note is sounding, and can still play in the gaps.
  • Echoes never interrupt a held key. Legato lines stay clean, and echoes come out at the ends of phrases and in rests.
  • Release tails: an echo either waits for the previous note's release envelope to finish, or cuts it off for a choppier, more rhythmic sound.
  • Alternatives: route echoes to another channel, or ping-pong between the pulses, when you want echoes to overlap new notes instead of yielding to them.

Echo events go into a small queue in NES RAM with a timestamp and the note that spawned them, which is what makes the cancel and duck rules possible.

Fat mode

Most NES MIDI builds give you five monophonic voices to sequence separately. Fat mode flips that. You play one part and the ROM decides how to spread it across the hardware: bass on the triangle, chord tones on the pulses, extra intervals baked into DMC loops, and noise for attack and grit. The aim is more apparent polyphony and more character than the five channels usually give. A patch here is a recipe for how the channels work together, not settings for one channel.

Voice roles in chord mode

ChannelRoleNotes
TriangleBassTakes the lowest held note, optionally an octave down. No volume control, so it's gated; the $4011 trick below gives it crude dynamics.
Pulse 1 and 2Chord tonesTake the next notes up. With few notes held, they double a note with detune instead.
DMCExtra intervalsA looped sample holding a dyad or triad, covering the notes the pulses can't. One channel, several pitches.
NoiseTextureAttack transient, breath, grit, or tuned short-mode noise for metallic overtones. Velocity-driven.

That gives roughly five or six sounding pitches from one keyboard part, before tricks.

Fat mode play styles

Chord split

As above: lowest note to bass, the rest distributed upward.

Stack (unison)

One note fattens into everything: pulses detuned a few cents apart and beating, triangle as a sub-octave, DMC loop an octave or fifth above, noise on the attack. A mono lead or bass that sounds much bigger than one channel.

Poly with overflow

Notes are allocated to channels until they run out. Extra notes either arpeggiate on one pulse (the classic chip way of faking polyphony) or get folded into the DMC loop.

Chord memory and strum

One key plays a stored chord shape, transposed. Optional strum staggers the channel note-ons by a few milliseconds, low to high or high to low.

Pedal steel mode

The channels that can't bend become a feature. On a pedal steel some strings bend while others ring at fixed pitch underneath; here the pulses bend and the DMC loop and triangle hold still. Everything is driven by the two controls every keyboard has, the pitch bend wheel and the mod wheel, with no expression pedals required.

Roles

  • Fixed strings: DMC loop (root and fifth, or a drone) and triangle bass. They ignore bends.
  • Pedaled strings: the two pulses. Each one bends by its own amount.

The wheels as pedals

  • Pitch bend up = pedal A. Instead of bending every voice by the same amount, each pulse moves by an interval set by the patch. With the wheel fully up, one pulse might rise a whole step while the other rises a half step; partway up gives the in-between bend, exactly like half-pressing a pedal.
  • Pitch bend down = knee lever. A second set of per-voice intervals, usually lowering, so one wheel gives two different chord changes.
  • Mod wheel = pedal B. A third set of intervals, stackable with the bend wheel, so pedal combinations are possible (wheel up plus mod wheel gives A+B).
  • Chord-aware bends (optional). Rather than fixed per-channel amounts, the bend depends on which chord tone a pulse is holding: a pulse on the 2nd rises to the 3rd, a pulse on the 3rd rises to the 4th, a pulse on the root stays put. One wheel move turns sus2 into major, or major into sus4, whatever notes you're holding. Factory presets can borrow classic E9 steel pedal changes.
  • Normal mode is still available: the bend wheel bends the pulses together by the RPN range, and the fixed channels stay fixed.

Automatic steel moves (no controller needed)

  • Bend into the note: pulses start below the played pitch and glide up into it, with interval, time and curve set per patch. Can be limited to certain voices, or to notes played above a velocity.
  • Volume swell: a slow attack envelope on the pulses so notes fade in without a pick attack, while the drone keeps its level.
  • Resolution beating: the DMC loop sits slightly off equal temperament, so a pulse resolving onto a chord tone beats against it briefly as it lands, like a steel settling in.
  • Bar slide (legato mode): all pulses glide together to the new chord while the DMC either holds or steps through its 16 rates for a crunchy, stair-stepped slide.

Smart voice allocation

  • Voice leading: when the chord changes, keep common tones on the same channel and move the others the shortest distance, so channels don't retrigger unnecessarily.
  • Priority rules: bass and top note are protected; inner voices get dropped into the DMC layer or the arpeggiator first.
  • Velocity spreads across layers: harder playing brings in more noise, a brighter duty, a louder DMC velocity layer.

Character tricks

  • Detune beating between the two pulses, and between pulses and the DMC loop. Because the DMC only has 16 rates, its pitch lands near the pulses but rarely on them, which gives a chorus-like wobble for free.
  • The $4011 pump. The DMC output level changes how loud the triangle and noise channels are, through the NES's nonlinear mixer. Writing to it gives the triangle crude volume control, or a rhythmic ducking effect. It clicks, which is part of the appeal.
  • Duty sweeps on the pulses for PWM-like movement.
  • Sweep unit for slow pitch drift or dive-bomb attacks.
  • Phase-reset clicks as a deliberate attack transient (clicky mode).
  • Short-mode noise for pitched metallic tones that sit on top of a chord.
  • Natural compression: the NES mixes channels nonlinearly, so big chords squash together in a pleasing way.

Drums and samples

Baked kits (the main approach)

  • Curated kits baked into ROM banks and bank-switched into $C000–$FFFF, where the DMC can read them.
  • Drum map with choke groups (open hat chokes closed hat, etc.).
  • Layered hits that fire several channels at once: DMC sample + noise burst + triangle pitch drop, for fatter kicks and snares or longer decays.
  • Velocity layers: DMC has no volume control, so loud and soft versions of a hit are encoded separately and chosen by velocity.
  • Mix of sampled and synthesized drums per kit.

Looped chord pads

  • Short looping DMC samples of chords in each key, for pads and drones.
  • Clicks, drift and odd tuning are part of the sound, not problems to engineer out. The builder offers several loop length/rate variants per chord and you pick by ear.
  • A "drift amount" setting lets loops wander, stopping short of the point where the output pins at the top or bottom and goes thin.

Where the DMC loops come from

Option A: baked

Pre-rendered loops for intervals and chord shapes in every key, built by the ROM builder web app and bank-switched in. Works on any mapper. Limited to the shapes you bake, and each costs ROM.

Option B: synthesized on the NES

If a mapper provides writable RAM at $C000–$DFFF, where the DMC can read it, the ROM renders loops on demand:

  • Any interval, any chord shape, any volume, from a sine or other wave table.
  • Encoding is cheap per bit, but a loop takes a few frames to render, so common shapes get cached and new ones are built just ahead of when they're needed.
  • Rewriting the loop while it plays changes the timbre live, like a crude wavetable.
  • The slew limit (output moves 2 steps per bit) rounds off loud, high waves into something triangle-ish and gritty. Fine for this sound.

Candidates: MMC5 (may allow PRG-RAM in that range) or FDS mode (32 KB of RAM at $6000–$DFFF). Both need checking on the N8 Pro.

Honest limits

  • DMC loops don't bend smoothly. This is the basis of pedal steel mode, where they deliberately stay fixed. Other options per patch: step through the 16 rates, or re-render the loop (option B only).
  • Triangle has no real volume, beyond the $4011 trick.
  • Chord changes cost time when a new DMC loop has to be rendered. Caching and predicting help; a brief glitch on a surprise chord is acceptable.
  • It's still five channels. Dense voicings will get arpeggiated or thinned.

ROM builder web app

A page on this site that builds a custom ROM, so the NES code never needs editing to change sounds.

  • Drop in WAVs, convert to DMC in JavaScript, preview the result as the NES would play it.
  • Build kits: note map, choke groups, layers, velocity splits.
  • Generate chord loops with the variant picker.
  • Edit presets (envelopes, vibrato, arp, echo) and MIDI channel mapping.
  • Output a .nes file to copy to the SD card or send over USB.

Open questions

To verify before writing 6502 code:

  • How a running game reads USB bytes on the N8 Pro: register addresses, whether bytes pass straight through or need a command or custom mapper. Look in krikzz/EDN8-PRO, especially the edlink-n8 source.
  • Whether games can read files from the SD card, or only the OS can.
  • Whether the N8 Pro's MMC5 core allows PRG-RAM at $C000–$DFFF.
  • How the N8 Pro shows up on macOS (expected: a /dev/cu.usbmodem… serial port) and whether Web Serial can open it.
  • Which bridge board can act as a USB host for the N8 Pro reliably, and how fast it can push bytes.
  • Whether Fat Chip 64's MIDI rate limits for the Teensyboy and MidiNES leave room for the extra CCs Fat Chip NES would want.
