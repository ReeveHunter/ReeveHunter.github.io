Why build this

MidiNES is great but hard to control. Its pitch bend handling is erratic, it has no vibrato, and anything expressive currently lives in Logic Scripter plugins and MIDI FX. The goal is to move all of that onto the NES, so that plain MIDI from any source sounds right: Logic, a keyboard, or a Raspberry Pi playing MIDI files at a show.

The Everdrive N8 Pro makes this possible without new hardware. It has a USB port that a running program can read, and SynthNes already proves the link works for live MIDI control.

Signal path

  1. Logic → IAC Driver. Enable the IAC bus in Audio MIDI Setup and route tracks to it.
  2. IAC → web page. A page on this site uses Web MIDI (navigator.requestMIDIAccess()) to listen. Chrome or Edge only.
  3. Web page → cart. Web Serial (navigator.serial) writes bytes to the N8 Pro's USB serial port. Selecting the port requires one click; after that the page can reconnect automatically.
  4. NES. The ROM polls the cart for incoming bytes and writes to the APU.

The page can send compact pre-digested messages instead of raw MIDI where that helps, but the long-term goal is for the ROM to handle raw MIDI itself so a Pi can drive it with no special software. The same page also runs in Chromium on a Pi.

Tempo-synced features (echo, arpeggiator) need tempo. The page forwards MIDI clock (24 pulses per quarter note) from Logic, or the ROM falls back to an internal tempo set by CC.

Keep from MidiNES

  • Full access to every channel: two pulses, triangle, noise, DMC, including sweep, duty, volume and length registers. One MIDI channel per NES voice, with channel numbers configurable so it coexists with other gear.
  • Fast CC response, not tied to vblank. Modulation (vibrato, envelopes) runs on its own fixed internal tick so it sounds the same regardless of how much data is arriving.
  • Decay on CC11, expanded into a full ADSR.
  • The pulse modulation hack (CC12/CC06 in MidiNES).
  • Keyboard-mapped sample banks, DMC pitch, and the "wave traveller," with better-curated kits.
  • A visualizer showing notes, CCs and active voices. Also useful for debugging.

Fix #1: pitch bend

  • Work in cents, not register units. The NES sets pitch with a period register, so equal register steps are tiny bends at low notes and huge ones at high notes. The ROM converts every pitch offset (bend, vibrato, glide, detune) to cents, sums them, then converts once to a period by interpolating between semitones in a period table. A bend sounds the same size in every octave. This is the same "sum in semitone space, convert once" approach as the Scripter plugin.
  • Use all 14 bits of the pitch bend message.
  • Bend range via RPN 0, default ±2 semitones, adjustable to ±12 or ±24.
  • Bend is channel state: a held bend applies to new notes, like a normal synth.
  • Clean/clicky switch per channel. Writing a pulse channel's high period byte restarts the waveform and clicks. Clean mode only writes the high byte when it changes (with the standard workaround to avoid even that); clicky mode just writes it.
  • Known limit: at the top of the range the period register is coarse, so very high bends step audibly. That is the hardware.

Fix #2: built-in vibrato

  • Standard controls: CC1 (mod wheel) for depth, plus CC76 rate, CC77 depth, CC78 delay.
  • Depth in cents, so vibrato is even across octaves.
  • Shapes: sine, triangle, square, saw, random (sample and hold).
  • Delay and fade-in per note, so vibrato blooms after the attack.
  • Tremolo and duty modulation from the same LFO engine. Tremolo is steppy with only 16 volume levels, which suits the sound.
  • Optional tempo sync for LFO rate.

Expression features

Carried over from the Logic Scripter work so they no longer need Logic:

  • Portamento/glide: CC5 time, CC65 on/off, legato mode, multiple curve shapes including S-curve.
  • ADSR volume envelopes for pulse and noise. Triangle has no volume control, so it gets gate only (see the $4011 trick in Fat NES).
  • Pitch envelopes for attack and release bends, and for synthesized drums (triangle kick, noise snare).
  • Hold/latch for detune and the mod hack, so new notes inherit them.
  • Program changes recall presets baked into the ROM by the builder.
  • Panic on CC120/CC123.

Arpeggiator

The defining chiptune trick: hold a chord, and one channel cycles through its notes fast enough to imply the chord.

  • Modes: up, down, up-down, as-played, random, and "tracker" mode (fixed semitone offsets like 0 4 7 from the played note, the classic 0xy effect).
  • Rate: free (in NES frames, where 1 frame is the classic buzzy chord) or tempo-synced divisions.
  • Octave range 1 to 4, and an optional gate length per step.
  • Latch so the arp keeps running after keys are released.
  • Works with pitch bend and vibrato, since everything sums in cents before conversion.

Echo

Built into the ROM so it replaces Logic's MIDI FX echo, and something most trackers only fake by hand.

ParameterOptions
Repeats1 to 8 (or more if RAM allows)
Velocity curveLinear, exponential (feedback %), or a custom curve drawn in the builder. Mapped to NES volume steps, so quiet tails get grainy, which is fine.
TimingTempo-synced divisions (1/4, 1/8, dotted, triplet) from MIDI clock, or free time in milliseconds
RoutingSame channel, or to another channel (e.g. pulse 1 echoes onto pulse 2), or ping-pong between the two pulses
Per-repeat changesOptional: duty cycle steps, pitch offset per repeat (rising/falling echoes), shortened gate

Priority: newest note wins

Each NES channel plays one note at a time, so echoes and new notes compete for the same channel. The default rule is that new note presses, and their own echoes, always take priority over echoes of older notes.

  • Cancel or duck (per patch). Cancel: a new note-on drops every pending echo of older notes. Duck: older echoes are only skipped while a newer note is sounding, and can still play in the gaps.
  • Echoes never interrupt a held key. Legato lines stay clean, and echoes come out at the ends of phrases and in rests.
  • Release tails: an echo either waits for the previous note's release envelope to finish, or cuts it off for a choppier, more rhythmic sound.
  • Alternatives: route echoes to another channel, or ping-pong between the pulses, when you want echoes to overlap new notes instead of yielding to them.

Echo events go into a small queue in NES RAM with a timestamp and the note that spawned them, which is what makes the cancel and duck rules possible.

Drums and samples

Baked kits (the main approach)

  • Curated kits baked into ROM banks and bank-switched into $C000–$FFFF, where the DMC can read them.
  • Drum map with choke groups (open hat chokes closed hat, etc.).
  • Layered hits that fire several channels at once: DMC sample + noise burst + triangle pitch drop, for fatter kicks and snares or longer decays.
  • Velocity layers: DMC has no volume control, so loud and soft versions of a hit are encoded separately and chosen by velocity.
  • Mix of sampled and synthesized drums per kit.

Looped chord pads

  • Short looping DMC samples of chords in each key, for pads and drones.
  • Clicks, drift and odd tuning are part of the sound, not problems to engineer out. The builder offers several loop length/rate variants per chord and you pick by ear.
  • A "drift amount" setting lets loops wander, stopping short of the point where the output pins at the top or bottom and goes thin.

Later: synthesized samples in RAM

If a mapper puts writable RAM at $C000–$DFFF (possibly MMC5, or FDS mode), the ROM can synthesize DMC loops itself: sine waves and simple intervals at any volume, rendered on demand. Rewriting a loop while it plays gives wavetable-style timbre changes. Details and the Everdrive questions are in Fat NES, which depends on this most.

ROM builder web app

A page on this site that builds a custom ROM, so the NES code never needs editing to change sounds.

  • Drop in WAVs, convert to DMC in JavaScript, preview the result as the NES would play it.
  • Build kits: note map, choke groups, layers, velocity splits.
  • Generate chord loops with the variant picker.
  • Edit presets (envelopes, vibrato, arp, echo) and MIDI channel mapping.
  • Output a .nes file to copy to the SD card or send over USB.

Open questions

To verify before writing 6502 code:

  • How a running game reads USB bytes on the N8 Pro: register addresses, whether bytes pass straight through or need a command or custom mapper. Look in krikzz/EDN8-PRO, especially the edlink-n8 source.
  • Whether games can read files from the SD card, or only the OS can.
  • Whether the N8 Pro's MMC5 core allows PRG-RAM at $C000–$DFFF.
  • How the N8 Pro shows up on macOS (expected: a /dev/cu.usbmodem… serial port) and whether Web Serial can open it.
